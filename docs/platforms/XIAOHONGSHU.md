# 小红书采集手册

本手册记录通过 Playwright MCP 操作小红书真实页面时的可复用步骤。页面结构会变化，选择器需在每次任务中先验证。

## 1. 搜索

- URL 模板：`https://www.xiaohongshu.com/search_result?keyword=<URL 编码关键词>&source=web_explore_feed`
- 结果卡片包含标题、作者、相对时间、点赞/评论数；卡片数量不等于已采集文章数。
- 未登录时出现登录弹窗；暂停，请用户在可见 Chrome 中完成。

## 2. 打开笔记详情

**必须从搜索结果卡片真实点击进入。**

- 直接拼接 `https://www.xiaohongshu.com/explore/<id>` 会返回 404（`error_code=300031`）。
- 通过页面点击进入时，URL 会自动附带 `xsec_token`，页面正常加载。
- 入库只保存不带 token 的规范链接；不得逆向、复制或复用 token。
- 点击方式：先用 `browser_snapshot` 取得链接 `ref`，再用 `browser_click` 点击，或使用页面可见的链接/按钮。

## 3. 详情读取

- 读取：标题、规范 URL、页面显示发布时间或相对时间、正文中的有限事实、评论入口计数。
- 正文多为图文混合；只记录可读文字与自写摘要，不下载图片/视频，不复制长正文。
- 相对时间（如“2天前”“昨天 21:13”）原样保留，不推算绝对时间。

## 4. 评论

1. 滚动到评论区；页面可能显示“共 N 条评论”。
2. 一级评论 ≤50：采集全部可访问评论；>50：切换/记录排序，高赞前 30 + 最新前 20，去重补足。
3. 楼中楼：点击“展开更多回复”“展开 N 条回复”等真实入口，继续展开子回复；保留父子层级。
4. 评论可能分批加载；滚动或点击“加载更多”后再读取。
5. 分别记录页面显示总数、实际采集一级数、页面显示回复数、实际楼中楼数、排序策略、覆盖状态。
6. 不保存作者昵称、头像、用户 ID、主页、位置或联系方式；评论文本中的手机号/邮箱/微信/QQ 需脱敏。

## 5. 常见问题

| 现象 | 处理 |
|---|---|
| 登录弹窗 | 暂停，请用户手动登录；不索取密码 |
| 直接 URL 404 | 回到搜索结果，点击卡片进入 |
| “展开更多评论” | 点击后等待加载，再继续读取 |
| 评论需登录 | 暂停；用户确认后继续；仍不可用则标 `blocked` |
| 验证码/风控 | 暂停交回用户；不绕过 |
| 限流/403 | 停止该批，记录时间与现象，继续另一平台 |
| 页面结构变化 | 停止该批，更新本手册后再继续 |

## 6. 禁止

- 不调用隐藏/逆向接口，不抓取登录态数据，不使用代理池或指纹伪装。
- 不保存评论作者身份字段与联系方式。
- 不进行点赞、收藏、评论、关注、私信、发帖等互动。
- 不伪造点赞数、评论总数、排序方式或发布时间。

## 7. 已验证的批处理动作（V5/V5.1）

- 动作片段：`scripts/employment/browser/actions.py` 的 `XHS_EXPAND_AND_PARSE`。
- 前提：先从搜索结果真实点击进入笔记（URL 自动带 `xsec_token`）。
- 行为：滚动 `.note-scroller`、点击 `.show-more` 展开回复、按 `.parent-comment` 数量做稳定检测（连续 3 轮不增长即停）、最后一次追加展开后解析。
- 层级：`reply-container` 内的回复递归解析，不限定只有第二层；父子关系按 DOM 容器恢复，不以文本全局去重。
- 解析字段：`.comment-item` 的 `id`（去掉 `comment-`）、`.content`、`.interactions .like .count`、`.info .date`、`.reply-container .comment-item`。
- 输出：标题、规范 URL（去 query）、`displayed_total`、`items`；Python 侧再执行 50 条规则、脱敏与覆盖判定。
- 已验证：12 篇固定样本中 8 篇；与逐步基线相比完整覆盖一致。更深的第三层若有真实页面出现，需再次实机验证选择器。
