# 就业情报研究规范

本文件规定就业情报工作流的来源分类、核验标准、日期处理与输出要求。适用于 `tasks/EMPLOYMENT_*.md` 及其他同类研究任务。

## 1. 研究边界

- 只研究**公开可见**的招聘信息、就业政策、行业报道与求职经验。
- 不采集私人信息、账号 ID、联系方式、头像、学校明细等非任务必需数据。
- 不替代官方招聘渠道；不把 UGC 当作职位开放、薪资水平或截止日期的证据。
- 平台条款、robots 规则和技术限制优先于任务 KPI；冲突时停止自动化并如实报告。

## 2. 届别与招聘阶段

`cohort`：

- `2026`：2026 届毕业生；
- `2027`：2027 届毕业生；
- `unknown`：无法从内容确认时使用，**不得**按采集日期推断。

`recruitment_stage`：

- `autumn` 秋招、`spring` 春招、`makeup` 补录、`early` 提前批、`internship` 实习转正、`other` 其他、`unknown` 未说明。

不同届别分开统计。同一链接若涉及多个届别，应分别记录或明确标注主届别，不得覆盖已有信息。

## 3. 主题与来源类型

`topic` 建议取值：

- `recruitment`：招聘公告、岗位、截止时间；
- `experience`：面经、笔试、简历、投递节奏；
- `policy`：就业政策、落户、补贴、签约规则；
- `industry`：行业趋势、裁员/扩招报道；
- `salary`：薪资反馈与讨论；
- `warning`：虚假招聘、培训贷、收费陷阱等风险提示。

`source_type`：

| 取值 | 含义 | 可信度处理 |
|---|---|---|
| `official` | 企业官网、政府部门、高校就业中心等一手来源 | 事实优先采用，仍需记录核验时间 |
| `reported` | 有来源的媒体报道 | 尽量回溯原始出处；无法回溯时降级 |
| `ugc` | 知乎回答、小红书笔记等用户内容 | 只能作为经验/观点，不推定为普遍事实 |
| `search_lead` | 仅搜索索引线索，未打开或未核实 | 不得当作已阅读原文 |

## 4. 核验状态

`verification_status`：

- `unverified`：尚未核验，默认值；
- `verified`：有可追溯的 `verification_url` 与 `verified_at`；
- `conflicting`：多个来源说法冲突，需在摘要中说明；
- `stale`：信息已过期或岗位已关闭。

**硬性规则**：

1. 标 `verified` 必须同时提供证据 URL 与核验时间；缺少任一字段时拒绝写入。
2. 不得用猜测、模型记忆或“行业常识”补全发布日期、截止日期、薪资数字。
3. UGC 不因点赞多或重复出现而升级为 `official`。
4. 页面打不开、需要登录或平台限制时，保持 `unverified` 并在报告中写明原因。

## 5. 日期与时间

- `published_at`：内容在源头显示的发布时间；不可见时留空。
- `collected_at`：本次实际观察时间（UTC ISO-8601），由工具自动写入。
- `verified_at`：完成核验的时间（UTC ISO-8601）。
- 不得把采集日期当作发布时间，也不得把旧帖描述为“最新”。

## 6. 平台访问与人工协作

1. 先阅读平台现行协议页，再决定是否可自动浏览。
2. 优先使用独立持久化浏览器 Profile；Profile 必须位于仓库之外。
3. 出现登录、二维码、短信/邮箱验证、设备确认、CAPTCHA、Cloudflare 或风控提示时，立即停止并请用户在可见浏览器窗口完成。
4. 用户完成验证后先复查页面可访问性；如果平台仍限制自动访问，停止该平台采集。
5. 只操作页面正常可见的搜索、点击、滚动与详情页导航；不调用隐藏接口、不逆向 API、不伪造指纹。
6. 条目上限、关键词与停止条件以任务文档为准；不得为凑数重复计数。

## 7. 记录与摘要

每条记录至少包含：

- `platform`、`canonical_url`、`title`；
- `source_type`、`topic`、`cohort`、`recruitment_stage`；
- `summary`（Agent 自写、简短、客观，不复制长正文）；
- `collected_at`、`verification_status`；
- 可选：`company`、`city`、`published_at`、`verification_url`、`verified_at`。

摘要要求：

- 只写页面中可确认的事实与作者明确表达的观点；
- 区分“帖子称”与“已核实”；
- 不写个人可识别信息；
- 不复制超过必要范围的原文。

## 8. 官方交叉核验

- 仅访问任务文档逐个列明的官方站点。
- 用于核验招聘公告、截止日期、政策条款等客观事实；不用于批量抓取招聘库。
- 核验结果写入 `verification_url` / `verified_at`，并在报告中给出结论与日期。
- 官方页面也无法确认时，保持 `unverified` 或 `conflicting`。

## 9. 报告要求

`runs/<run-id>/report.md` 至少包含：

1. 本次任务、run-id、执行时间与访问方式；
2. 知乎、小红书分别的访问状态（可采集 / 需人工登录 / 不允许自动访问 / 受阻）与证据；
3. 2026 届与 2027 届分节统计：条数、主题分布、典型来源链接；
4. 已核验事实与核验来源；未核实项清单；
5. 平台限制、登录协作与停止原因；
6. 与 SQLite 实际记录数的一致性核对；
7. 明确未执行的操作（下载、互动、私信、批量采集等）。

禁止把“未打开”“登录未完成”“平台受阻”写成“已完成”。
