# 就业生态搜索策略（V6.2）

研究目标：**2023–2028 年中国青年与普通劳动者的真实就业生态**——毕业生与学历、招聘平台、工资收入、五险一金、实习试用、裁员争议、外包派遣、待业回老家、工厂基层、互联网、制造业、医药医疗、租房攒钱、城市流动、转行。

V6.2 起基础关键词库为 **250 个**（原有 100 个全部保留 + 新增 150 个），年份/届别/身份修饰词独立维护、不计入这 250 个。

机读配置：`tasks/employment/search_keywords.json`。本文件是人工说明；两者需同步。

## 3. 四级搜索调度（V6.2）

1. **主题多样性**：按"目标 − 已采集 − 队列中"的缺口比例选择维度，不反复搜秋招类词。
2. **年份/届别多样性**：修饰词按下标轮换，每次一个；历史年份、当前年份、届别交替覆盖。
3. **实际产出优先**：已搜索过的关键词按 `accepted / searches` 排序，高产出方向优先复用；低产出降低权重。
4. **动态关键词**：
   - `python -m kato_engine.agent.cli dynamic-scan --platform xiaohongshu` 从真实文章标题/摘要提取候选；
   - 候选写入 `engine_dynamic_keywords`，状态默认 `candidate`，**不会自动进入查询队列**；
   - 人工 `dynamic-approve --keyword ...` 后才由调度器读取，来源与基础 250 词分开记录。

### 调度指标

每个关键词记录：搜索次数、发现候选数、跨关键词去重后新候选数、入库命中数、详情进入成功数、相关性合格数、每次搜索新增有效文章数、最近一次搜索时间。

### 重复率口径

分开统计：批内重复、与历史候选/已入库重复、无效 URL、详情进入失败、内容不相关。**不得把搜索结果数当作有效采集数。**

## 4. 分类规则（不得用搜索词直接赋值）

每篇文章必须按页面内容判断：

- `employment_topic`：十个维度之一或 `other`；
- `employment_status`：`job_seeking` / `employed` / `probation` / `left` / `unemployed` / `waiting` / `career_change` / `other` / `unknown`；
- `industry`：计算机、机械、制造、金融、服务业等；无法确认留空；
- `graduation_cohort`：`2026` / `2027` / `other` / `unknown`；
- `event_year`：事件发生年份（整数）或空；
- `employment_type`（辅助）：正式工 / 外包 / 劳务派遣 / 实习 / 合同工 / 灵活就业；
- `benefits`（辅助）：社保、公积金、包吃住、餐补、年终奖、补贴（可多标签）；
- `salary_reported`：页面是否包含实际薪资描述（0/1/空）；
- `experience_type`：`personal` / `secondhand` / `recruitment_ad` / `opinion` / `unknown`。

**关键区分**：包含“2026”不代表 2026 届；“2026 被裁”可能是工作十年的员工。事件年份、届别、就业状态必须分别确认，无法确认标 `unknown`。

## 5. 批次与配额

- 每批尽量覆盖多个主题，记录每主题候选数、唯一数、重复数、失败数；
- 维护主题采样数与目标差额，避免单一热门话题占绝大多数；
- 兼顾正面、负面、中性经历，不因负面帖子热门而重复放大同类内容；
- 每完成一批，更新关键词候选队列与主题覆盖统计。

## 6. 真实测试要求

在小红书、知乎分别测试工资、求职、裁员、进厂/制造业、秋招等主题，记录：

- 搜索词、页面候选数、有效候选数、重复数；
- 点击进入详情成功率；
- 内容与目标的相关性；
- 新增唯一文章数。

仍执行：每篇最多 50 条一级评论，所选评论下尽可能完整楼中楼，作者身份不入库。
